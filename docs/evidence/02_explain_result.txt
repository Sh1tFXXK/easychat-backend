- 执行：`sqltool run sql/02_explain_offset_vs_cursor.sql`（逐条执行并打印结果集）

## 结论摘要

| 场景 | type | EXPLAIN rows | EXPLAIN ANALYZE 实际扫描 | 备注 |
|---|---|---|---|---|
| B 深偏移 `LIMIT 4000,20` | `ref` | 9816 | **4020 行** | 索引定位到了用户区间，但必须吐出 4020 行再丢掉前 4000 |
| C 游标 `create_time < 锚点 LIMIT 20` | `range` | 1000 | **20 行** | 从锚点反向读一页，扫描量与页深度无关 |
| D1 删索引 + 深偏移 | `ALL` | 49816 | — | `Using filesort`，全表扫 |
| D2 删索引 + 游标 | `ALL` | 49816 | — | 没有索引时游标也救不了，仍是全表扫 |
| D4 重建索引 + 游标 | `range` | 1000 | — | `ALL → range` 的原始证据 |

> 注意：B 段 EXPLAIN 的 `rows=9816` 是估算值（该用户实际 5,000 行），
> 所以"深分页扫了多少"必须看 `EXPLAIN ANALYZE` 的 `actual rows`，不能只看 `EXPLAIN`。
